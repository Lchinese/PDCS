# 9.云端及Minikube部署

## 9.1 部署概述

### 部署目标

本章节介绍云原生微服务电商系统在阿里云ECS服务器上，基于Docker + Minikube完成全量部署的完整过程。系统包含4个Spring Boot后端微服务、1个React前端应用和4个中间件，全部以容器化方式运行在Kubernetes集群中。

后端调试存在两种方式：一是在Windows本地通过IDEA直接启动Spring Boot服务，连接Docker单机中间件（MySQL/Redis/MongoDB），使用HTTP Client或curl测试端点，便于快速联调；二是将服务打包为Docker镜像加载到Minikube集群，通过K8s Service DNS通信测试端点，验证与生产环境一致。

### 部署环境

| 项目 | 说明 |
|------|------|
| 服务器 | 阿里云ECS Ubuntu 22.04（4核8G） |
| 公网IP | 8.163.\*\*.\*\*\* |
| Kubernetes | Minikube v1.32.0（Docker驱动） |
| K8s版本 | v1.28.3 |
| Java | OpenJDK 17 + Maven 3.6.3 |

### 部署成果

- **9个** Pod全部正常运行（1/1 Running）
- **4个** 中间件（Redis、MySQL、MongoDB、MinIO）运行正常
- **4个** 微服务（user-service、product-service、cart-service、order-service）运行正常
- 前端web-server（1/1 Running）运行正常
- 所有服务间网络互通，K8s Service DNS解析正常

### 前端部署架构

**构建与打包**

前端采用 React **19** + Vite **8** 开发，部署流程为：

```
源码 → npm run build → dist/ 静态文件 → Docker镜像(nginx:alpine) → K8s Pod → NodePort:30080
```

Dockerfile（frontend/Dockerfile）：

- 基础镜像：nginx:alpine（轻量级Web服务器）
- 将dist/构建产物复制到/usr/share/nginx/html/
- 注入自定义nginx.conf反向代理配置
- 暴露80端口

K8s部署（k8s/web-deployment.yaml）：

- Deployment：1副本，镜像web-frontend:v1
- Service类型：NodePort，端口80→容器80，对外映射30080端口
- 云端访问地址：http://8.163.\*\*.\*\*\*:30080

### 前端页面路由

前端使用 React Router（BrowserRouter），页面包括：

| 路由 | 页面 | 权限要求 |
|------|------|----------|
| / | 首页（商品列表） | 公开 |
| /login | 登录/注册 | 公开 |
| /products/:id | 商品详情 | 公开 |
| /cart | 购物车 | 需登录 |
| /orders | 订单列表 | 需登录 |
| /payment/:id | 支付页 | 需登录 |
| /profile | 个人中心 | 需登录 |
| /merchant | 商家后台 | 需MERCHANT角色 |
| /admin | 管理员后台 | 需ADMIN角色 |

### K8s集群内服务发现

在Minikube K8s集群中，各服务通过K8s Service DNS互相通信：

| 服务名 | 端口 | 用途 |
|--------|------|------|
| mysql-service | 3306 | MySQL数据库（user/order共用） |
| mongodb-service | 27017 | MongoDB数据库（商品/评价） |
| redis-service | 6379 | Redis缓存（购物车） |
| minio | 9000 | MinIO对象存储（头像） |
| user-service | 80→8081 | 用户微服务 |
| product-service | 80→8082 | 商品微服务 |
| cart-service | 80→8083 | 购物车微服务 |
| order-service | 80→8084 | 订单微服务 |
| web-service | 30080→80 | 前端Nginx（NodePort） |

环境变量通过K8s YAML注入，如order-service的跨服务调用配置：

- CART\_SERVICE\_URL=http://cart-service:80
- PRODUCT\_SERVICE\_URL=http://product-service:80
- USER\_SERVICE\_URL=http://user-service:80

### 认证与鉴权数据流

1. 用户登录 → POST /users/login → 返回JWT Token
2. Token存入 → localStorage('token')
3. Axios请求拦截器 → 自动附加 Authorization: Bearer \<token\>
4. 后端JwtAuthFilter → 验证Token有效性
5. 401响应 → 前端自动清除Token并跳转登录页

### 本地开发 vs 云端部署对比

| 对比项 | 本地开发 | 云端/Minikube部署 |
|--------|----------|-------------------|
| 前端访问 | http://localhost:5173 | http://\<IP\>:30080 |
| API代理 | Vite proxy（vite.config.js） | Nginx反向代理（nginx.conf） |
| 后端地址 | localhost:8081~8084 | K8s Service DNS名称 |
| 数据库 | localhost:3306/27017/6379 | mysql/mongodb/redis-service |
| 代理配置 | **7条**路径（含/reviews、头像/图片上传） | **6条**路径（含/reviews、/files/文件代理） |

## 9.2 整体部署架构

### 整体架构

```
阿里云ECS (8.163.**.***)
└── Docker宿主机
    └── Minikube容器 (Docker驱动)
        └── K8s集群 (v1.28.3)
            ├── 中间件层
            │   ├── Redis Pod   (redis:7)                ← cart-service
            │   ├── MySQL Pod   (mysql:8.0)              ← user-service / order-service
            │   ├── MongoDB Pod (mongo:6.0)              ← product-service
            │   └── MinIO Pod   (minio:latest)  :9000    ← user-service（头像存储）
            ├── 微服务层
            │   ├── user-service Pod    (:8081) → mysql-service:3306 + minio:9000
            │   ├── product-service Pod (:8082) → mongodb-service:27017
            │   ├── cart-service Pod    (:8083) → redis-service:6379
            │   └── order-service Pod   (:8084) → mysql-service:3306
            └── 接入层
                └── web-server Pod (nginx:alpine + React dist)
                    :30080(NodePort) → :80(Nginx)
                    ├── /*           → /index.html（SPA前端路由）
                    ├── /users/*     → user-service:80
                    ├── /products/*  → product-service:80
                    ├── /reviews/*   → product-service:80
                    ├── /cart/*      → cart-service:80
                    ├── /orders/*    → order-service:80
                    └── /files/*     → user-service:80 → MinIO读取
```

### 服务端口与网络映射

| 服务 | 容器端口 | K8s Service端口 | 说明 |
|------|----------|-----------------|------|
| user-service | 8081 | 80→8081 | 用户微服务 |
| product-service | 8082 | 80→8082 | 商品微服务 |
| cart-service | 8083 | 80→8083 | 购物车微服务 |
| order-service | 8084 | 80→8084 | 订单微服务 |
| web-server | 80 | NodePort:30080 | 前端Nginx |
| MySQL | 3306 | 3306 | 集群内部 |
| MongoDB | 27017 | 27017 | 集群内部 |
| Redis | 6379 | 6379 | 集群内部 |
| MinIO | 9000 | 9000 | 集群内部 |

### 数据库选型与分配

| 微服务 | 数据库 | 选型理由 |
|--------|--------|----------|
| user-service | MySQL | 用户数据需要事务（注册+余额初始化），结构化强 |
| order-service | MySQL | 订单需要ACID事务（创建订单+扣库存+扣余额） |
| product-service | MongoDB | 商品属性差异大，需要动态Schema，评论松耦合 |
| cart-service | Redis | 购物车高频读写，基于内存，Hash结构天然匹配 |

### 服务间调用关系

前端Nginx通过反向代理将 /users、/products、/reviews、/cart、/orders、/files 分别转发到对应的微服务。order-service在创建订单时需要跨服务调用cart-service（获取/清空购物车）、product-service（查询价格/库存）和user-service（查询余额）。各微服务间通过K8s Service DNS名称互相访问，无需硬编码IP。

## 9.4 MinIO容器部署

### 部署概述

项目使用MinIO作为对象存储服务，替代本地文件系统存储用户头像等非结构化数据。MinIO通过MinIO Java SDK（8.5.7）与user-service集成，部署在Minikube K8s集群中，使用S3兼容API提供文件上传与读取服务。

### 部署架构

```
用户浏览器
    │
    ▼
Nginx (web-server Pod, NodePort:30080)
    │
    ├── /files/{filename} → user-service:80 → MinioClient → MinIO Pod(:9000)
    └── /users/{id}/avatar → user-service:80 → MinioClient.putObject → MinIO Pod(:9000)
```

### K8s部署配置

| 配置项 | 值 |
|--------|-----|
| 镜像 | quay.io/minio/minio:latest |
| 副本数 | 1 |
| API端口 | 9000 |
| 控制台端口 | 9001 |
| 用户名/密码 | admin / admin123456 |
| 存储卷 | emptyDir（非持久化，Pod重建数据丢失） |
| 启动命令 | 自动创建/data/avatars目录后启动 |
| Service名 | minio（与代码MINIO_ENDPOINT一致） |

### user-service集成配置

- Maven依赖：io.minio:minio:8.5.7
- K8s环境变量（user-deployment.yaml）：MINIO\_ENDPOINT=http://minio:9000

MinIO连接参数：

| 配置项 | 默认值 |
|--------|--------|
| endpoint | http://minio:9000 |
| access-key | admin |
| secret-key | admin123456 |
| bucket-name | avatars |

### 文件上传与读取流程

**头像上传（写入MinIO）：**

POST /users/{id}/avatar → Nginx → user-service → MinioClient.putObject → MinIO

返回URL: /files/{filename}，存入数据库User.avatar字段

**头像读取（从MinIO读取）：**

GET /files/{filename} → Nginx → user-service → MinioClient.getObject → 返回图片二进制

### 关键实现

- **Bucket自动初始化**：user-service实现CommandLineRunner，启动时自动创建avatars bucket
- **JWT豁免**：/users/files/路径在JwtAuthFilter中设为公开访问，浏览器无需Token即可加载图片
- **Content-Type识别**：根据文件后缀自动设置jpeg/png/gif/webp类型，缓存策略max-age=31536000

### Nginx代理配置

```nginx
location /files/ {
    proxy_pass http://user-service:80/users/files/;
}
```

Nginx将/files/请求转发到user-service，user-service再通过MinIO SDK从MinIO Pod获取文件返回给浏览器。

### 部署实施

**镜像离线传输：**

```bash
# 本地拉取并导出
docker pull quay.io/minio/minio:latest
docker save quay.io/minio/minio:latest -o minio.tar

# 上传到服务器 → 加载到Minikube
scp minio.tar root@8.163.**.***:/root/
CONTAINER_ID=$(docker ps -q -f name=minikube)
docker cp /root/minio.tar $CONTAINER_ID:/var/lib/docker/tmp/minio.tar
docker exec $CONTAINER_ID docker load -i /var/lib/docker/tmp/minio.tar
```

**部署与验证：**

```bash
kubectl apply -f k8s/minio-deployment.yaml
kubectl get pods
# 输出: minio-64f6754758-wxn4h   1/1   Running   0   23m
```

验证结果：头像上传 → MinIO存储 → 前端显示，全链路验证通过。

### 已知问题与解决

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| Service名不一致导致DNS失败 | Service名minio-service，代码用minio | 统一Service名为minio |
| 图片加载返回401 | JWT拦截/users/files/路径 | JwtAuthFilter设为公开路径 |
| Pod重启后图片丢失 | emptyDir卷无持久化 | 建议改用PVC（5Gi） |

### 部署总结

| 项目 | 说明 |
|------|------|
| 部署方式 | Minikube K8s单Pod |
| 存储类型 | emptyDir（建议升级PVC） |
| 集成服务 | user-service（MinIO SDK 8.5.7） |
| 文件类型 | 用户头像（jpeg/png/gif/webp） |
| 访问路径 | /files/{filename} → Nginx → user-service → MinIO |
| 运行状态 | 1/1 Running，全链路验证通过 |

## 9.5 Dockerfile设计

### 后端微服务Dockerfile

所有后端微服务采用统一的Dockerfile结构，基于Eclipse Temurin 17 JDK Alpine镜像（通过1ms.run镜像代理拉取）。以user-service为例，完整Dockerfile如下：

```dockerfile
FROM docker.1ms.run/library/eclipse-temurin:17-jdk-alpine
LABEL maintainer="ecommerce-team"
WORKDIR /app
COPY target/user-service-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8081
ENV JAVA_OPTS="-Xmx256m -Xms128m"
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD wget -qO- http://localhost:8081/actuator/health || exit 1
```

各微服务Dockerfile结构完全一致，仅jar文件名、EXPOSE端口和个别JVM参数不同：

| 微服务 | COPY的jar文件 | EXPOSE | 特殊配置 |
|--------|--------------|--------|----------|
| user-service | user-service-0.0.1-SNAPSHOT.jar | 8081 | 无 |
| product-service | product-service-0.0.1-SNAPSHOT.jar | 8082 | 无 |
| cart-service | cart-service-0.0.1-SNAPSHOT.jar | 8083 | 无 |
| order-service | order-service-0.0.1-SNAPSHOT.jar | 8084 | JAVA_OPTS额外含 `-Duser.timezone=Asia/Shanghai` |

设计要点：
- 使用1ms.run镜像代理解决国内无法直接拉取Docker Hub镜像的问题
- Alpine基础镜像体积小（约200MB）
- JVM内存限制 `-Xmx256m -Xms128m` 适配Minikube有限内存
- HEALTHCHECK通过 `/actuator/health` 端点供K8s自动检测服务状态
- Spring Boot Fat JAR由 `mvn clean package` 生成，文件名格式为 `<service>-0.0.1-SNAPSHOT.jar`

### 前端Dockerfile与Nginx配置

前端构建为静态文件后打入Nginx镜像，完整Dockerfile如下：

```dockerfile
FROM nginx:alpine

# 复制前端构建产物到Nginx默认目录
COPY dist/ /usr/share/nginx/html/

# 复制自定义Nginx反向代理配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

Nginx配置中，/users、/products、/reviews、/cart、/orders、/files 共**6条**反向代理规则分别转发到对应微服务的K8s Service，其余请求通过 try\_files $uri $uri/ /index.html 返回前端页面，确保React Router的前端路由不会返回404。

## 9.6 K8s部署配置

### 中间件部署

系统共部署 **4个** 中间件，每个中间件均包含Deployment和Service两部分：

- **MySQL**（mysql-service:3306）：使用mysql:8.0镜像，通过环境变量设置root密码和初始数据库名ecommerce，配置PVC声明1Gi持久化存储空间挂载到/var/lib/mysql，确保数据不丢失。
- **MongoDB**（mongodb-service:27017）：使用mongo:6.0镜像，同样配置PVC 1Gi持久化存储挂载到/data/db。
- **Redis**（redis-service:6379）：使用redis:7镜像，无需持久化存储，配置最简。
- **MinIO**（minio:9000）：使用quay.io/minio/minio:latest镜像，使用emptyDir存储，启动时自动创建avatars目录。

### 微服务部署

各微服务的Deployment通过环境变量连接对应的中间件Service。以cart-service为例，通过 REDIS\_HOST=redis-service 和 SPRING\_DATA\_REDIS\_HOST=redis-service 连接Redis；order-service则需要配置多个环境变量实现跨服务调用：

```yaml
env:
  - name: MYSQL_URL
    value: "jdbc:mysql://mysql-service:3306/ecommerce"
  - name: CART_SERVICE_URL
    value: "http://cart-service:80"
  - name: PRODUCT_SERVICE_URL
    value: "http://product-service:80"
  - name: USER_SERVICE_URL
    value: "http://user-service:80"
```

所有微服务Service统一将对外端口80映射到容器内部端口（8081~8084），前端web-service使用NodePort:30080对外暴露。

## 9.7 部署实施过程

### 镜像离线传输方案

由于阿里云ECS无法直接拉取Docker Hub镜像（TLS handshake timeout），采用离线传输方案：

```bash
# 1. 在本地Windows下载并保存镜像为tar文件
docker pull <image>:<tag>
docker save <image>:<tag> -o D:\<image>.tar

# 2. 上传到阿里云服务器
scp D:\<image>.tar root@8.163.**.***:/root/

# 3. 在服务器加载到宿主机Docker
docker load -i /root/<image>.tar

# 4. 复制到Minikube容器内加载（解决minikube image load卡住问题）
CONTAINER_ID=$(docker ps -q -f name=minikube)
docker cp /root/<image>.tar $CONTAINER_ID:/var/lib/docker/tmp/
docker exec $CONTAINER_ID docker load -i /var/lib/docker/tmp/<image>.tar
```

### 中间件部署

按上述方案依次传输redis:7、mysql:8.0、mongo:6.0、minio:latest四个镜像到Minikube，然后执行 kubectl apply 部署：

| 中间件 | 镜像 | 部署命令 | Pod状态 |
|--------|------|----------|---------|
| Redis | redis:7 | kubectl apply -f k8s/redis-deployment.yaml | 1/1 Running |
| MySQL | mysql:8.0 | kubectl apply -f k8s/mysql-deployment.yaml | 1/1 Running |
| MongoDB | mongo:6.0 | kubectl apply -f k8s/mongodb-deployment.yaml | 1/1 Running |
| MinIO | minio:latest | kubectl apply -f k8s/minio-deployment.yaml | 1/1 Running |

### 微服务编译与部署

每个后端微服务的部署流程统一为：Maven编译 → Docker构建 → Minikube加载 → K8s部署

| 微服务 | Maven编译耗时 | Docker镜像 | Pod状态 |
|--------|--------------|------------|---------|
| cart-service | 约30秒 | cart-service:v1 | 1/1 Running |
| user-service | 约1分41秒 | user-service:v1 | 1/1 Running |
| product-service | 约17秒 | product-service:v1 | 1/1 Running |
| order-service | 约10秒 | order-service:v1 | 1/1 Running |
| web-server | — | web-frontend:v1 | 1/1 Running |

以cart-service为例，完整命令如下：

```bash
cd /root/ecommerce-project/cart-service
mvn clean package -DskipTests
docker build -t cart-service:v1 .

# 加载到Minikube
docker save cart-service:v1 -o /tmp/cart-service.tar
CONTAINER_ID=$(docker ps -q -f name=minikube)
docker cp /tmp/cart-service.tar $CONTAINER_ID:/var/lib/docker/tmp/
docker exec $CONTAINER_ID docker load -i /var/lib/docker/tmp/cart-service.tar

# K8s部署
kubectl apply -f /root/ecommerce-project/k8s/cart-deployment.yaml
```

其余微服务流程完全相同，仅目录和镜像名不同。

## 9.9 已知问题与解决方案

| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| Docker镜像拉取超时 | TLS handshake timeout | 国内网络无法访问Docker Hub | 本地下载 → docker save → scp上传 → docker load |

| MinIO Service名不一致 | 头像上传成功但无法显示 | Service名minio-service，代码用minio | 统一Service名为minio |
